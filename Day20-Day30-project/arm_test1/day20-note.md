## 交叉编译 ---  利用linux下x86架构，st公司或者其他服务商的提供的交叉编译工具，编译为arm架构的的32位的二进制文件，然后进行烧录（有具体的工具）
交叉编译/   
    ├──架构分类与概念：x86架构64位环境下与arm架构32位环境下的可执行文件的互传烧录
    ├──分为：st公司通用的交叉编译工具包、arm公司的交叉编译工具包、还有其他厂商的定制的交叉编译工具包    
    ├──使用：
        |——解压工具包-获取工具包的bin的路径-然后放到系统环境内
            |——WSL下属于和windows共用cpu和资源，所以以防污染主机资源，系统配置文件的修改，仅个人用户使用，单独放置个人用户家下即：~（也就是/home）
                |——指令：echo 'export PATH=$PATH:~/tools/gcc-arm-9.2-2019.12-x86_64-arm-none-linux-gnueabihf/bin' >> ~/.bashrc
                    |——echo    打印或者输出
                    |——‘’      纯文本
                    |——export  把一个变量设置为“环境变量”，这样它就能被子进程（比如后来敲的 gcc 命令）继承。
                    |——PATH=$PATH:  新路径：这其实是核心！
                    |——PATH 是一个系统变量，里面存了一堆文件夹路径，用冒号隔开。当敲 ls 或 gcc 时，Linux 会去这些文件夹里挨个找这个程序。
                    |——$PATH 代表“把原有的路径保留下来”。
                    |——: 代表追加。
                    |——后面的长串路径，是编译器所在的 bin 文件夹，即pwd绝对路径。完整意思是：告诉系统，以后找程序时，除了原来的地方，再多去这个新路径找找。
                    |—— >>：这叫“追加重定向”，把前面 echo 打印的内容加到文件的末尾，而不是覆盖原来的内容。
                    |—— ~/.bashrc：这是每次打开 WSL 终端时，系统自动会去读的配置文件。
                    |——这一整行翻译过来就是：把“以后去哪找这个编译器”这句话，永久写入Bash 配置文件里。
                    |——source ~/.bashrc  ：source（或简写为 .）：意思是“重新读取并执行这个文件”。
            |——linux属于虚拟的完整的内核空间和分配的处理器，所以可以放置linux内核文件的里面，全局共享
                    |——必须把编译器放到 /usr/local/arm/，这是 Linux 系统的“全局目录”，方便以后任何用户都能用。
                    |——修改 /etc/profile 是“全局配置文件”，普通用户没权限改，所以必须加 sudo 而且要手动用 vi 打开。
                    |——改完必须“重启系统”，因为 /etc/profile 只在登录时读取。

文件传输/
    ├── rz和sz是Linux/Unix同Windows 进行Zmodem文件传输的命令工具,都使用Zmodem文件传输协议。
        |——基本含义
            sz（Send Zmodem）：用于将文件从Linux/Unix服务器发送到本地Windows系统，即下载文件到本地。sz命令利用ZModem协议，可以一次传输一个或多个文件 
            rz（Receive Zmodem）：用于从本地Windows系统上传文件到Linux/Unix服务器，即接收文件。运行rz命令后会弹出文件选择窗口，用户可以选择要上传的文件 
        ├── rz：从电脑传到板子（接收）。
        ├── sz 文件名：从板子传到电脑（发送）。
        ├── 如果板子系统里提示 rz: command not found，说明这个工具没装。可以直接在板子里敲：apt install lrzsz
        ├── 终端里打印出 Transfer complete ，意味着 Windows 上的文件已经通过串口线，成功“输送”进了真实板子的 Linux 系统里！
    ├──使用场景
        |——适用于在Linux服务器和Windows客户端之间进行文件传输。
        |——需要Windows端支持ZModem协议的Telnet/SSH客户端，如Xshell或SecureCRT，PuTTY等部分工具不支持 
        |——常用于开发、运维或生物信息分析中，将数据上传到服务器或下载分析结果到本地查看
    |——常用操作
        |—— -a：以文本方式传输（ASCII）。
        |—— -b：以二进制方式传输（Binary）。
        |—— -e：对控制字符进行转义，保证文件传输正确。
        |—— -q：安静执行，不输出提示信息。
        |—— --ymodem：使用YModem协议。
        |—— --version / --help：显示版本信息或帮助信息

文件权限赋值ls -al查看，chmod使用/
在 Linux 里，任何文件都有 “用户、组、其他人” 三类归属，每一类都有 “读、写、执行” 三种权限。
    -rw-r--r--：主人可以读、写（rw-），同组人只能读（r--），其他人只能读（r--）。 没有 x，所以不能运行。
    -rwxr-xr-x：主人可以读、写、执行（rwx），同组人可以读、执行（r-x），其他人可以读、执行（r-x）。 有了 x，就能运行了。

第1位	            第2-4位	               第5-7位	           第8-10位
- 或 d	            文件所有者（User）	    所属组（Group）	     其他人（Others）
- 普通文件，d 目录	 主人的权限	             组人的权限	          陌生人的权限   

在 Linux 里，r、w、x 对应着特定的数字：
        r = 4
        w = 2
        x = 1
        把三种权限加起来：
        主人：读(4) + 写(2) + 执行(1) = 7
        同组人：读(4) + 执行(1) = 5
        其他人：读(4) + 执行(1) = 5

        所以 755 就是 rwxr-xr-x 的数字写法！
        而普通的配置文件（比如 .txt），通常写 644（主人能读写，别人只能看）。
