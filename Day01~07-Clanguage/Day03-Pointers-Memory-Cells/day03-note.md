#********************************明确区分栈（Stack）和 堆（Heap）。
Stack（栈）：自动管理，LIFO（后进先出），静态开辟，系统开辟大小固定（通常几MB,8MB左右），编译器进行分配，速度极快，存储局部变量和函数调用帧。
Heap（堆）： 手动管理（malloc/free），动态开辟，灵活，大小受限于系统RAM，速度较慢，存储动态分配的内存。

stack vs heap
管理方式：系统自动 vs 程序员手动。
速度与大小：栈快且小 vs 堆慢且大。
生命周期：随函数结束销毁 vs 直到手动free。

地址通常有巨大的差距（栈地址通常很大，在0x7ff...附近。  堆地址不同heap的首地址，通常在 0x55... 或 0x1... 开头（远离栈区的内存池）
栈：速度极快，但空间极小（默认通常只有 8MB 左右）。如果在栈上开个 int arr[1000000]，程序立马崩溃报错（栈溢出）。
堆：速度较慢（因为要找空闲的内存块），但空间极大（几乎受限于电脑的物理内存）。基本存大图片、大数组，都得用堆。

#*****************************************函数指针（包含函数指针数组和结构体内函数指针使用）核心优势 + 工程实际场景：
1、低耦合分层：底层驱动和业务逻辑分离，互不依赖；
2、易扩展：新增功能不用修改原有核心代码，避免大量分支；
3、代码复用：通用框架一套，通过传入不同函数实现不同行为；
4、运行时动态绑定：程序跑起来随时切换执行逻辑，静态数组 / 分支做不到；
5、封装模拟面向对象：结构体绑定数据 + 操作，嵌入式驱动标准架构；
6、简化代码：消除臃肿 if/switch，用查表替代，可读性、执行效率更高、写通用工具函数，功能由外部传入，复用性极强。
场景：
工业 / 嵌入式高频使用场景汇总：
1、硬件中断回调：按键、定时器、串口、ADC；
2、菜单 / 状态机：函数指针数组做菜单选择、设备状态切换；
3、通用算法库：qsort 排序、通用遍历、通用计算；
4、设备驱动框架：结构体绑定 init/read/write 接口；
5、操作系统钩子函数：任务创建、异常、心跳回调；
6、协议解析：不同指令对应不同处理函数，查表分发。

坑点：
1、函数指针不能加减运算（和数组指针区分）
2、调用时类型不匹配（参数个数 / 返回值必须完全一致）
3、不要返回局部函数指针：函数内部定义的函数指针是局部栈变量，返回它本身没问题；
                      但如果指针存了局部栈变量的操作函数，不会悬空，因为函数在代码段，永久有效。

#*****************************************指针数组和数组指针
指针数组：int *p[5]
定义与内存模型：
int a=10, b=20, c=30;
int *p[3] = {&a, &b, &c};

p 是数组，有 3 个格子，每个格子存 int 变量的地址；
典型用途：字符串数组 char *str[4] = {"aa","bb","cc","dd"}

核心区分总结：
指针数组 = 数组，元素全是指针，sizeof 很大；多用于字符串、多个变量地址存储。
数组指针 = 单一指针，只能存完整数组的地址，sizeof 永远等于系统指针宽度；多用于遍历二维数组。
赋值区分：
指针数组：p[0] = &num; 存普通变量地址
数组指针：p = &arr; 只能存整个数组地址 &数组名

****** 补充：int (*arr[5])[10]; —— 数组指针数组（进阶：数组里每个元素是数组指针）
#include <stdio.h>
int main(void)
{
    int arr[5] = {1,2,3,4,5};
    int (*p)[5] = &arr;

    printf("p原始地址：%p\n", p);
    p++;
    printf("p++后地址：%p\n", p);
    return 0;
}
输出示例（地址差值固定 20）：
p原始地址：0x7ffeefbff560
p++后地址：0x7ffeefbff574
十六进制 0x74 - 0x60 = 20，偏移 20 字节。
数组指针自增时，一次跳过它指向的完整数组总字节数，这也是二维数组遍历最核心的底层原理。
